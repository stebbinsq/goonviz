# GoonViz (codename Prism): notes for Claude

Live visual synth for a projector, two front-ends sharing presets/shaders/palettes/params/maps:
- **web/**: Chrome web app (WebGL2, Web MIDI, getUserMedia). The user's main target now: MacBook Air M3
  and an Intel MacBook Pro, built-in webcam, Akai MPD32. To be hosted at **goonviz.live** (domain at name.com)
  via GitHub Pages from the `gh-pages` branch (`tools/deploy_web.sh` pushes a subtree split of `web/`;
  `web/CNAME`). The gh token lacks `workflow` scope, so there's no Actions workflow. `web/bundle.js` is generated by
  `tools/build_web.py`; never edit it by hand.
- **prism/** (Python + moderngl + pygame-ce): the Raspberry Pi version.
See README.md for user-facing docs.

Branding: user-facing name is **GoonViz**; internal code names (`prism/` package, `prism.*` storage keys,
`PRISM_DATA`) stay as is.

## Web status (2026-10-29)

- 30 presets: originals (1–17), kaleidoscopic set (18–23), Jade set (24–27, inspired by the user's request for
  "Jade Cicada"-style organic visuals), 3D raymarched set (28–30, Tipper-inspired: rendered-looking fractal
  worlds with beat-snapped camera moves). 10 palettes.
- Glitch fixes: preset changes melt via uTransition in composite.glsl; autopilot never glides knobs a shader
  rounds (stepped_knobs / steppedKnobs scan for floor( / int( lines); audio noise floor 0.015 so quiet laptop
  mics aren't auto-levelled into fake hits. The web exposure readback is async (PBO + fence); web adaptive
  resolution lives in App.adaptResolution (snaps the refresh estimate to real display rates).
- Autopilot lives in prism/autopilot.py and web/js/autopilot.js (ports of each other); intensity is the
  `ap_intensity` param. Auto-exposure (Engine._meter / Engine.meter) reads the composited frame's 1x1 mip.
- tools/build_web.py stamps `?v=<hash>` onto script tags so browsers never mix stale and fresh files.

- All 17 presets compile as GLSL ES 3.00 in Chrome; MPD32 logic verified with simulated MIDI in the browser.
  Not yet tried with a real MPD32 or webcam in Chrome, or on the Intel MacBook.
- The camera channel order differs per platform: shaders use the `VIDEO_SWIZZLE` macro (bgr in Python, rgb on the web).
- Publishing needs the user's OK: GitHub repo (account stebbinsq; commit as the noreply address
  123203145+stebbinsq@users.noreply.github.com), Pages custom domain, and DNS at name.com (the user does that).

## User's gear

- Akai MPD32 → `maps/akai_mpd32.json`, built on its factory preset 18 "ArkaosVJ" (CC 1-72, latching pads).
  Pad note numbers are assumed (36-99), not documented; `run.py --learn-pads` fixes them if wrong.
- Insta360 X4 over USB in Webcam Mode: 2:1 equirectangular 360 video (`video.source: "insta360"`).
  Whether its mic appears as USB audio is unverified; audio falls back to the default input.
- Projector on HDMI 0.

## Things to verify on first hardware run

## Aesthetic direction (user feedback)

Very trippy, in the visionary-art style of Glass Crane and Android Jones: luminous filigree on dark
backgrounds, jewel-tone palettes, bloom, sacred geometry, depth. **No "MS Paint" looks**: no flat fills,
plain rainbow gradients or hard posterization. Preview changes with `tools/render_presets.py` and look at
the contact sheet before calling a preset done.

## Conventions

- Presets: `presets/NN_name.glsl` with a `// @preset {json}` header, defining `vec3 scene(vec2 p, vec2 uv)`.
  Use `pal()`/`glowpal()` (shared palettes), not hard-coded colours.
- After changing the MPD32 map, regenerate the printable sheet: `python tools/make_cheatsheet.py`.
- Test venv on the Mac needs: moderngl numpy pillow pygame-ce mido python-rtmidi sounddevice.
